# Design

## Context

动机见 proposal.md。dashboard 与 options 分别用 JSON.parse 后发送 IMPORT_RECORDS；store.mergeImport 按 ID 更新，否则公司岗位去重。toCsv 导出 21 个中文表头但没有 ID，状态历史仅有次数。buildRecord 把空 appliedAt 补为当前时间，不能直接用于未投递的 CSV 行。现有 workbench 在异步导入期间阻止模式切换，可复用此保护。用户提供的 117 行 CSV 是兼容性验收样例，含 18 条旧岗位及 99 条公司级记录（45 已投递、54 未投递）。

## Goals / Non-Goals

**Goals:** 共享解析／规划逻辑和入口 UI；纯本地、确定性预览；CSV 只追加且不覆盖；JSON 原有合并兼容；失败可重试。

**Non-Goals:** XLS/XLSX、分号／制表符文件、云端同步、自动查企业性质、恢复 CSV 缺失的截图与历史、恢复全局设置、修改现有用户 CSV 或知识库导入。

## Decisions

1. **格式先选，文件后选。** 两个入口复用共享导入弹层，阶段为格式／文件、映射、核对、提交、结果；选择格式决定 accept 与解析器，不仅通过扩展名推测。JSON 也增加结果预览，保留旧备份形状和记录合并方式。相比一个隐藏文件输入，用户更容易理解格式差异。
2. **新增 application-import 纯模块。** 解析 CSV、解码、字段别名、严格日期验证、候选归一化、重复规划独立于 DOM 与 chrome。用状态机扫描引号字段，不用 split(',')；无新增外部依赖，10 MiB／10000 行硬上限，预览分页（每页 50 条）避免 DOM 堆积。默认 UTF-8 fatal 解码，手动 GB18030 可重解，字符有效但乱码时仍能切换编码。
3. **映射白名单。** 使用 toCsv 当前业务列，允许常见别名（公司名称／岗位名称／投递日期）和明确英文模型名；去除表头 BOM 和两端空白，重复表头按源列索引呈现、不自动猜测。禁止目标重复映射；无关列忽略但提示。skills 按导出分隔符斜线拆分并去重；企业性质沿用 normalizeCompanyType。状态变更次数只展示警告，不映射为 statusHistory。
4. **CSV 专用记录构造。** 后台重新验证候选白名单、日期、公司与用户决定，新 ID 仅后台生成；createdAt 缺省为本次导入时间、appliedAt 空值为 null、updatedAt 为提交时间。新记录只生成一次“CSV 导入”状态事件，不伪造历史。日期通过年月日组件验证，使用本地时间，拒绝自动滚动和模糊 Date.parse；不推测未提供的岗位／日期／状态。非空自定义状态原样保留，空状态使用配置默认值并预览提示。危险 HTML 只按文本展示，链接遵循现有安全 URL 展示限制。
5. **CSV 和 JSON 各自提交语义。** CSV 的公司岗位归一化键与现有 util.normalizeKey 保持一致，同库／批内重复默认跳过，允许显式另存，绝不经 mergeImport 覆盖。JSON 使用原 mergeImport，预览明确同 ID 更新，不以 CSV 白名单裁剪旧字段；设置页和 dashboard 均检查 res.ok，避免失败后成功提示。JSON 不增加全局设置恢复。
6. **最新数据和串行写入。** CSV 预览结果带候选选择及重复基线摘要；新路由后台在招聘记录写入串行队列中重新规划并一次 saveRecords，重复集合发生变化则返回重新核对，不写入。为保证此语义，新增／更新／删除／清空／JSON 导入等招聘记录写入路由也纳入同一队列，纯存储函数避免嵌套锁；不改变知识库队列。JSON 在最新数据上重新计算，若更新／跳过计划变化也退回核对。候选仅保留内存，确认后以提交令牌去重重复请求；失败释放可重试，成功令牌在当前 worker 生命周期内缓存结果，worker 重启后重新获取记录核对。
7. **共享弹层与模式保护。** 建议新增 src/shared/application-import.js 与 CSS，DOM 通过 textContent／安全转义呈现。选择／核对阶段关闭无副作用，提交时禁用重复按钮与关闭；失败保持候选。向 view-state 钩子声明忙碌状态，防止 pending 导入切换模式丢失。核对面板在窄侧栏用纵向字段及分页，不新开标签页。

## Risks / Trade-offs

- [无 ID 无法可靠区分同公司同岗的多次投递] → 默认跳过、展示原记录日期状态，用户明确选择另存；不推测集团归属。
- [CSV 无截图与完整历史] → 导入预览和 README 明确损失，不按次数合成历史。
- [GB18030 可将无效字节映射成看似正常字符] → 编码选择与文字预览由用户确认，不静默猜测。
- [单个存储数组并发覆盖] → 所有招聘记录后台写入统一串行并在锁内读取最新状态；覆盖相关回归。
- [导入后刷新无法恢复未确认候选] → 明确候选仅内存，取消可重选；沿用切换保护，不承诺刷新恢复。
- [记录包含未知状态] → 沿用现有 statusChoices 对记录当前值的兼容，确保筛选展示可见且不擅自修改配置。

## Migration Plan

无需存储版本迁移。先实现纯解析／规划，再接入后台和两个 UI 入口，验证旧 JSON 与新 CSV 后更新 README 和分发包。回滚代码不会删除已导入记录；导入前建议用户导出 JSON。测试使用合成 fixture，用户 CSV 只读验收，不提交其内容为测试资产。
