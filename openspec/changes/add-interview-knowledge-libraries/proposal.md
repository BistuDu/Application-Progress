# Proposal

## Why

现有 Chrome 扩展可以追踪岗位投递，但只有岗位备注，无法按简历项目积累面试追问，也无法维护可复用的八股文知识。增加两个本地知识库，让用户以手工整理问答为主，并在需要时借助八股文资料生成贴合项目经历的回答草稿。

## What Changes

- 增加独立项目库：手动维护项目与问答，上传 PDF／Word 简历提取项目名称、简介和职责，经核对后保存；项目可用于多家公司的面试。
- 增加八股文题库：手动新增问答，支持分类、多标签、全文搜索、修改和删除。
- 两类问答使用 Markdown 答案与预览，每道题保存一份答案，允许答案暂时为空。
- 八股文录入支持网页框选、上传／粘贴图片，以及 Markdown／PDF／Word 文件批量导入；统一预览、编辑和选择保存，重复题逐条核对已有答案与新答案。
- 项目 AI 回答采用“自动匹配八股文参考题 → 用户增删参考题 → 生成草稿 → 用户编辑并保存”的流程，引用知识与个人项目事实分别处理。
- 数据保存在当前浏览器；只保存整理后的项目、问答与来源信息，识别所用原图和原始文件不作为附件保存。
- 提供覆盖两个知识库的 JSON 完整备份与恢复，以及 Markdown 导出。

## Capabilities

### New Capabilities

- `project-library`: 独立项目及项目面试问答的本地管理、Markdown 编辑与搜索。
- `technical-question-bank`: 通用八股文问答的分类、多标签、编辑与检索。
- `knowledge-ingestion`: 简历项目提取、截图与文件问答提取、来源记录、核对及重复题处理。
- `project-answer-assistance`: 八股文自动匹配、参考题手动调整、基于项目事实的回答草稿与确认保存。
- `knowledge-portability`: 两个知识库的版本化 JSON 备份恢复与 Markdown 导出。

### Modified Capabilities

无。当前没有已发布的 OpenSpec capability；现有岗位记录及 JD 识别行为继续保留。

## Impact

- 新增知识库页面及 `src/lib/` 下的独立存储、导入、Markdown、匹配与导出模块；在 popup／dashboard 增加入口。
- 扩展 `src/background.js` 消息路由和 `src/content/overlay.js` 框选流程，以显式目标区分 JD 与八股文识别；新知识库采用独立存储键，不复用岗位记录模型和公司／岗位去重规则。
- 复用 `src/lib/settings.js` 的接口地址、模型与域名授权机制；增加独立任务提示词及文本／多图请求能力，避免改写用户已有的 JD 提示词。
- 引入随扩展分发的 PDF、DOCX、Markdown 解析与安全渲染依赖；默认 Word 文件指现代 `.docx`，旧 `.doc` 的处理边界在设计中明确。
- 新增离线逻辑验证和隔离浏览器流程验证；保留既有岗位 JSON／CSV／Markdown 导入导出兼容性。知识库备份独立于岗位备份，不含 API Key。
- 第一版范围为单浏览器、人工维护与明确触发的 AI 辅助；账号同步、原始附件归档、多答案版本、刷题评分不在本次范围。
