# Design

## Context

动机与范围见 `proposal.md`。当前仓库是无构建工具的 MV3 Chrome 扩展：`src/background.js` 负责截图、联网和岗位写入，`src/content/overlay.js` 是动态注入的经典脚本；popup、dashboard、options 使用原生 HTML/CSS 和 ES modules。

- `src/lib/store.js` 在 `chrome.storage.local` 的 `records` 数组中保存岗位，去重键为公司与岗位，JSON 格式为 `app: jd-job-tracker, version: 1`。
- `src/lib/vision.js` 的请求、结果字段、空返回重试与提示词均专用于 JD；不能只换提示词就复用于多题提取。
- 截图支持当前可见网页框选；`startCapture` 默认进入岗位审阅，`lastCapture` 是内存缓存，`deliver` 失败会把 JD 结果写入 `lastResult`。
- 设置中已有接口地址、Key、模型、超时和可选域名授权；manifest 已具备 storage、unlimitedStorage、activeTab 与 scripting 权限。
- 目前没有项目模型、文档解析器、Markdown 渲染器或知识库测试。`scripts/selftest.mjs` 有存储替身与可选真实接口测试；`scripts/e2e-cdp.mjs` 使用隔离 Chromium profile。

这是跨页面、存储、文档解析与 AI 编排的新增能力，因此创建完整技术设计。

## Goals / Non-Goals

**Goals:**
- 用独立、可版本化的数据容器实现两库关系、统一问答编辑、核对与导出。
- 保持人工保存为正式数据的唯一入口，所有识别和生成先产生候选结果。
- 优先在本地解析、匹配和渲染；模型调用沿用现有配置，原始资料只在处理期间存在。
- 使重开页面、并发编辑、取消任务、导入失败和恢复失败具有可验证行为。

**Non-Goals:**
- 不引入后端、向量服务或账号体系；不将知识库塞入岗位备注。
- 不迁移既有岗位存储，也不全面重构 JD 视觉层或既有岗位备份。
- 不构建整套富文本编辑器、原始文件查看器或答案历史版本系统。

## Decisions

### 1. 独立知识库页面与共享编辑、核对组件

增加 `src/knowledge/knowledge.html`、`knowledge.css`、`knowledge.js`，在 popup 和 dashboard 提供入口。页面有“项目库”和“八股文题库”两个明确分区：项目分区左侧项目列表、右侧项目概况与问答；八股文分区左侧分类、右侧搜索、标签和题目列表。点击题目展开 Markdown 答案，并可进入编辑。

两区共享题目与答案编辑器、Markdown 预览、来源展示和保存反馈。人工新增题目允许答案为空。八股文支持分类管理和多标签输入；分类为单层，项目问答第一版按项目组织，不强制共用八股文分类。删除项目明确列出同时删除的题数；删除分类将其题目置为未分类。

替代方案是扩展已有岗位详情抽屉，但其字段、筛选和状态逻辑专用于投递，会混淆复用关系。独立页面同时减少对既有看板布局的改动。

### 2. 独立、版本化的本地存储与单一写入者

新增 `src/lib/knowledge-store.js`，使用一个独立键 `knowledgeLibrary` 保存完整容器：

```text
KnowledgeState
  schemaVersion, revision
  projects[]          id, name, summary, responsibilities, sources[], createdAt, updatedAt, revision
  projectQuestions[]  id, projectId, question, answerMarkdown, sources[], aiReferences[], timestamps, revision
  technicalQuestions[] id, question, answerMarkdown, categoryId?, tags[], sources[], timestamps, revision
  categories[]        id, name

Source
  type: manual | web-region | image-upload | image-paste | markdown | pdf | docx
  url?, pageTitle?, fileName?, pageNumbers[]?, importedAt

AIReference
  technicalQuestionId, questionTitle, referencedUpdatedAt, generatedAt
```

`timestamps` 指 `createdAt/updatedAt`。标签是去重字符串集合，避免新增不必要的标签关系表。每题只保存 `answerMarkdown` 一个当前答案；AI 草稿不是第二个正式答案，引用元数据不存参考答案副本。模型参数、原文件、base64 图片、完整响应和临时提示词都不进入容器。来源仅记可确定的信息，不从 DOCX 推测固定页码。

全部知识库写入通过 background 的独立消息路由串行处理，并对修改和删除校验实体 revision；恢复校验容器 revision。读取与写入使用字段白名单并验证身份、题目非空、项目归属与分类关系。一次导入提交和一次恢复均用单个容器写入；成功响应只在存储 Promise 成功后发送。跨页面通过 storage 变更通知刷新未编辑内容，编辑中的冲突保留用户输入并要求重载核对。

选择一个容器是为让两库关系、批量提交和恢复保持一致。多键数组更易出现部分恢复；IndexedDB 可用于更大的库，但当前纯文本、单浏览器范围无需新增数据库体系。每次写整个容器的成本作为容量风险监控。

### 3. 本地 Markdown 渲染与分发依赖

采用随扩展打包的 Marked 与 DOMPurify，原文是持久化唯一表示，HTML 仅为预览。标题、列表、代码围栏和行内代码优先支持，代码内容只作文本显示。预览清洗事件属性、脚本与危险 URI，来源链接只允许 HTTP(S)，不自动加载 Markdown 中的图片附件。依赖固定版本、包含许可证，位于 `src/vendor/`，页面使用本地脚本／模块；不得加载 CDN 或为了引入依赖放宽到远程脚本执行。

选解析器与清洗器组合而非自制正则渲染器，原因是代码围栏与列表等语法容易被简单替换破坏；Marked 官方明确说明其输出需要清洗。[Marked 文档](https://marked.js.org/)、[DOMPurify 官方仓库](https://github.com/cure53/DOMPurify)。

### 4. 文档解析与结构化提取分离

新增 `src/lib/knowledge-documents.js` 与 `knowledge-import.js`。

- **Markdown**：先用语法 token 识别题目标题及 Q／A 标记，保持围栏代码原文；本应用导出的结构使用确定性解析，题目和答案中的代码不参与分题。一般文档格式不清晰时以“待核对”块展示；用户可调整边界或主动执行模型拆分，不能把普通答案标题默认当作新问题。
- **PDF**：本地 PDF.js 逐页提取文字及页码；根据行位置组织段落并保留明显的代码缩进。无文字页渲染为内存 canvas 图像，交给视觉提取；混合 PDF 按页选择文字或图像路径。分页边界保留标记，跨页题目合并后记录来源页集合；无法判定的边界交给核对界面。选择 PDF.js 是因为可在浏览器中解析和渲染 PDF。[PDF.js 官方资料](https://mozilla.github.io/pdf.js/)、[示例](https://mozilla.github.io/pdf.js/examples/)。
- **DOCX**：本地 Mammoth 从 ArrayBuffer 提取结构化 HTML，经清洗后转为受控的标题、列表、段落和代码块中间表示；正文没有代码样式时由用户在预览中修订。嵌入图片只作为临时识别输入，不生成入库图片；不读取外部文件。Mammoth 支持浏览器 ArrayBuffer，但 Markdown 转换 API 已废弃，因此不依赖该接口。[Mammoth 官方文档](https://github.com/mwilliamson/mammoth.js#api)。

Word 默认支持 `.docx`；旧 `.doc` 给出转存 DOCX／PDF 的提示，这是未指定旧格式时的第一版兼容假设。损坏、加密 PDF、无法识别的文件类型不写库。

简历模式使用独立提示词，只提取项目概况和职责，不生成项目问题。题库模式只提取原文存在的题答，缺答案留空。文字文档按结构和页边界分块，单次输入以约 12,000 字符为初始上限，保留跨块上下文并合并候选；扫描页顺序处理。超过 20 MiB 的输入或超过单批 50 页的 PDF 提示拆分，不静默截断；这些是可根据实际模型调整的处理默认值，调整不得改变核对要求。图片压缩复用当前最长边与质量设置。

本地确定性拆分能在无 API Key 时导入清晰 Markdown；简历语义提取、一般文档 AI 拆题与视觉提取需要已有模型配置。所有路径仍由用户核对后保存。

### 5. 网页框选复用与目标隔离

新增题库框选入口放在 popup 和网页右键菜单。`startCapture`、selector 与后续分析显式携带 `target: job | technical-question`，缺省为 job，使既有快捷键与菜单仍执行 JD 流程。从原网页发起框选，避免在扩展知识库标签页上调用 activeTab 截图。

overlay 继续承担选择区域和取消；知识库目标使用独立候选问答审阅，不使用岗位字段或 `SAVE_RECORD`。为避免将 Markdown 和文档依赖注入第三方网页，框选识别完成后打开／复用知识库页面的核对面板，接收纯文本候选和来源。上传与主动粘贴由知识库页面 File／paste 事件处理，无需后台轮询剪贴板。

图片仅在 overlay、页面与 background 内存中传递。知识库目标完成、取消、失败或标签关闭后清理截图缓存，不经过现有岗位 `lastResult` 的持久化兜底；待核对的纯文本候选可用 session 存储交接并在处理后删除，但不得包含图片、文件字节或 Key。JD 目标继续原有流程。

### 6. 统一候选核对与重复题解决

手动题、图片识别和文件导入统一为候选集合：原候选身份、可编辑字段、来源、是否选中、可能冲突及用户决策。核对期间未选中的题和未处理的冲突不写入正式库；用户可保存已选且已解决的项，并看到新增／更新／保留计数。

八股文重复比较在该题库全局进行；项目手动问答只在同一项目内比较。题目规范化仅处理首尾空格、全半角、连续空白和编号前缀，保留关键技术符号与否定词。完全匹配提示冲突，近似匹配显示“可能重复”并允许用户判断是否同题，不自动合并近义题。批次内部使用相同规则。

选择原答案不更新正文；采用新答案或人工整理后更新原题并保留 ID，合并来源去重，保持已有 AI 引用关系。更新冲突提交前再次检查 revision，避免核对时原题已被其他页面编辑。相比按 ID 自动覆盖或自动跳过，逐条决策符合用户维护现有答案的习惯。

### 7. 自动检索、人工调整与 AI 草稿

新增 `src/lib/knowledge-match.js`，本地派生轻量检索索引：英文技术 token、中文连续词／二元片段与分类标签。查询使用当前题目、项目简介和个人职责；题目与标签权重高于答案正文，提供共同关键词作为匹配说明。默认展示最多 8 条候选并建议前 5 条有答案的题；用户可取消、查看正文并搜索全库补充。该实现满足自动匹配且不增加嵌入服务，候选数和权重可在保持人工调整的前提下优化。

新增 `src/lib/model-client.js` 与 `knowledge-ai.js`，复用设置中的 endpoint 候选、超时和权限函数，但使用任务专属的请求和输出验证。保留 JD 的 `vision.js` 字段及提示词原样。模型网络请求位于 background；页面与内容脚本不接收 API Key。任务区分 resume-projects、extract-questions 和 project-answer，支持纯文本与图像输入，返回结构化候选或 Markdown 草稿。

项目答案请求将项目事实、当前题目、可选已有答案和用户最终确认的参考问答分段传入。提示词声明参考资料是知识而非个人经历，缺乏证据的贡献与指标以“待补充”占位。请求不包含未选的八股文内容；输入过长时提示精简参考，不静默丢弃用户选择。用户可以在无匹配时明确选择仅按项目资料生成。

生成结果与既有答案并列预览；“保存采用”才更新唯一答案及 `aiReferences`。草稿绑定项目、题目、选择快照和实体 revision，输入变化时标记草稿过时并要求重新核对。引用存 ID、题目标题及使用时更新时间，删除后显示不可用，更新后显示已变化；两种情况均不改写已保存项目答案。当前答案不存参考知识的隐藏版本。

### 8. 请求生命周期与失败反馈

所有模型任务使用唯一 requestId、AbortController、当前超时与 keepalive 机制。后台结果必须校验任务仍有效，旧任务、取消任务和错目标结果不能覆盖当前编辑。解析异常、空返回、权限不足、模型不支持图片和容量问题保留可复制输入并支持重试。

多页识别显示页进度与失败页，不允许把失败描述当作题库内容。用户可处理已成功的候选，失败页继续重试；只有明确选择保存的核对结果入库。PDF 文件、canvas、object URL、剪贴板图与 pending 引用在结束时释放；session 只作为短暂文本候选交接，不参与正式备份。

### 9. 知识库备份恢复独立于岗位备份

新增 `src/lib/knowledge-export.js`：

- JSON envelope 为 `format: interview-knowledge-library`、`version: 1`、`exportedAt` 和 `data`。data 包含两库与分类；使用字段白名单，不遍历整个浏览器 storage，因此不会带出 Key 或岗位截图。
- 恢复先完整解析、校验唯一 ID、必要字段、项目归属、分类引用和版本，然后展示两库数量与将替换的范围。默认恢复是完整替换知识库，不是批量题目导入；确认后单次写入，维持项目和题目 ID，运行时 revision 重新分配。失效的 AI 引用允许保留为“来源不可用”，与本来允许删除参考题的模型一致。失败、取消、未知版本均不写库。
- Markdown 可导出一个或两个库；项目按名称／项目 ID 分组，题库按分类分组，包含来源、标签和参考题。固定分组标题，题目使用明确 Q 标记、答案使用明确 A 标记；保留正文 Markdown，处理标题层级与嵌套围栏，避免代码内文字误分题。使用内嵌文本元数据表示来源与标签，导入本应用导出文件时能恢复候选元数据；JSON 才是完整恢复格式。

Markdown 导出另带库格式标记，题目元数据记录原题面及答案行数，并以结束标记校验边界。确定性导入按行数读取答案，不将答案中的标题、Q／A 示例或元数据示例重新解释为分题指令；边界不一致时明确报错，不静默丢弃文字；不压缩正文及代码块中的空行。空项目和空库不产生候选题，旧版空库导出仍可识别。项目导出显示 AI 参考题及来源变化状态。

沿用 `downloadFile` 和文件名处理。现有 `toExportJson`、`mergeImport`、dashboard／options 的岗位备份入口保持既有格式与含义；知识库页面提供自己的备份、恢复与 Markdown 操作，不复用公司＋岗位去重。

### 10. 默认值与实现边界

未在讨论中指定的细节采用：单层自定义分类、每题一个分类加多标签、空分类进入未分类、无默认预置八股文内容。项目概况和题答来源都可人工修订。只有本次明确触发的提取或生成会调用模型，不自动补全所有空答案。

检索排名的具体权重、导出文件名样式和视觉间距为实现时可调参数，不影响规格、模块边界与任务顺序。

## Risks / Trade-offs

- [PDF／DOCX 的代码格式和题目边界不可靠] → 保留页及结构标记，跨页上下文提取，异常项进入核对；用实际多题、跨页、扫描和代码样例验证。
- [模型误把通用知识写成个人经历] → 明确分离事实与参考资料，缺失事实占位，并要求用户审阅保存；不能仅靠提示词宣称完全消除错误。
- [静态中文匹配遗漏同义表达] → 显示匹配依据并允许全库手动搜索，不把无匹配解释为没有相关知识。
- [整容器写入成本随文本库增长] → 顺序提交与输入防抖，保存可见失败，验证较大题库下的搜索与保存；需要更大规模时再迁移数据库。
- [MV3 任务或页面关闭导致识别中断] → 任务超时、取消、keepalive 与纯文本 session 交接；不以持久化原始附件换取恢复能力，必要时重新提供文件。
- [新增解析依赖增大扩展体积] → 固定本地依赖、按功能延迟加载、记录许可证与分发文件，保持手动录入不依赖文档解析初始化。
- [恢复完整替换可能抹去当前知识库新增内容] → 恢复预览明确替换范围，入口可先下载当前 JSON；不自动合并或无提示覆盖。

## Migration Plan

1. 新存储键首次读取时返回空容器，只有用户首次保存或确认恢复时写入。已有 records／settings 不迁移。
2. 加入页面、依赖和路由后加载新版扩展；旧快捷键和岗位备份维持原目标，新目标由新入口触发。
3. 验证 JSON 往返、Markdown 内容、跨页面冲突、取消／失败、无原始附件持久化以及 JD 回归后发布。
4. 回退到旧扩展版本时仍能使用岗位记录；知识库键留存但旧版本不读取。回退前可以导出知识库 JSON，新版本恢复读取该版本容器。
