# Spec Delta

## Purpose

把工作台和投递进度页重排为列表优先的布局，减少首屏装饰性内容占用，让用户在同屏看到更多投递记录，并保持清晰一致的视觉层级。

## ADDED Requirements

### Requirement: 工作台头部紧凑

工作台头部 MUST 在同一区域呈现标题、视图标签页、框选入口和显示模式控制。全屏宽度下这些内容 SHOULD 位于一行；侧栏或窄宽度下 MUST 不超过两行。窄宽度下框选入口 MAY 收进菜单，或收为带可读标签的图标按钮。在 360 CSS 像素宽度下 MUST NOT 出现横向页面滚动，标签和按钮 MUST 仍可点击。

#### Scenario: 全屏单行头部

- **WHEN** 工作台在宽度大于 900 CSS 像素的全屏模式打开
- **THEN** 标题、视图标签页、框选入口和显示模式控制位于同一行，内容不重叠

#### Scenario: 侧栏两行头部

- **WHEN** 工作台在约 400 CSS 像素宽的侧栏打开
- **THEN** 头部最多占两行，标签页和框选入口仍可操作，页面没有横向滚动

#### Scenario: 窄屏框选入口

- **WHEN** 侧栏宽度不足以同时显示「框选招聘 JD」和「框选题目」的完整文字
- **THEN** 框选入口收为图标按钮，仍可通过可读标签或悬停提示区分，并能分别触发对应框选

### Requirement: 可折叠数据概览

投递进度页 MUST 始终显示一行关键指标摘要，至少包含总记录、本周新增、进行中、Offer 和拒绝/结束。详细统计卡片和图表 MUST 默认收起，用户 MUST 能通过「数据概览」控制展开或收起。展开状态 MUST 持久化并在侧栏与全屏切换后保持。记录新增、删除或状态变化后，摘要和已展开内容 MUST 同步更新。

#### Scenario: 默认收起

- **WHEN** 用户首次打开改进后的投递进度页
- **THEN** 只看到一行关键指标，统计卡片和图表默认不显示，表格占据主要高度

#### Scenario: 展开数据概览

- **WHEN** 用户点击「数据概览」
- **THEN** 统计卡片、投递漏斗、趋势、来源分布和技能关键词显示，控制按钮状态变为可收起

#### Scenario: 记住展开状态

- **WHEN** 用户展开数据概览后刷新页面或切换侧栏/全屏
- **THEN** 数据概览保持展开，直到用户主动收起

#### Scenario: 指标同步更新

- **WHEN** 用户新增一条记录或修改记录状态
- **THEN** 摘要行的关键指标与展开后的统计内容都反映最新数据，无需手动刷新

### Requirement: 全高列表与吸顶

投递进度页 MUST 使用占满可用视口的纵向布局。默认收起概览时，页面本身 MUST NOT 需要纵向滚动，只有表格主体滚动；筛选栏和表头 MUST 在表格滚动时保持可见。数据为空或筛选结果为空时，空状态 MUST 显示在列表区域内且不破坏吸顶行为。侧栏和全屏模式都必须满足该行为。

#### Scenario: 表格内部滚动

- **WHEN** 记录数量超过当前视口可显示的行数
- **THEN** 用户在表格区域滚动时，页面顶栏、摘要、筛选栏和表头保持不动

#### Scenario: 表头吸顶

- **WHEN** 用户滚动到列表底部
- **THEN** 列标题仍可见，用户能知道每列含义

#### Scenario: 空状态

- **WHEN** 当前筛选没有匹配记录
- **THEN** 列表区域显示空状态提示，筛选栏和表头仍保持在原位

#### Scenario: 侧栏全高

- **WHEN** 在侧栏打开投递进度页并存在多条记录
- **THEN** 列表在侧栏剩余高度内滚动，不出现整页纵向滚动条

### Requirement: 紧凑行与地点截断

默认字号下，表格数据行高度 MUST 控制在 42–48 CSS 像素。地点 MUST 单行显示，超出可用宽度时截断，并 MUST 通过悬停提示或详情抽屉提供完整地点。公司/岗位单元格 MUST 最多显示两行；下一步 MUST 使用独立可选列，不得再通过公司单元格内的标签撑高行。记录时间、投递日期、薪资和来源 MUST 单行显示。

#### Scenario: 多地点截断

- **WHEN** 一条记录的地点包含六个城市
- **THEN** 表格中地点显示为单行摘要，行高不因地点增多而增加，用户可查看完整地点

#### Scenario: 下一步独立列

- **WHEN** 一条记录有下一步内容且该列处于显示状态
- **THEN** 下一步显示在自己的列中，公司/岗位单元格保持两行以内

#### Scenario: 长公司名与岗位名

- **WHEN** 公司名或岗位名超过列宽
- **THEN** 文本在单元格内截断，完整内容可通过悬停提示或详情抽屉查看

### Requirement: 视觉层级与状态呈现

投递进度页 MUST 使用统一的蓝灰视觉变量区分页面背景、卡片、正文、次级文字、分割线和主操作。状态 MUST 以「彩色圆点 + 文字」呈现，不得只靠颜色区分；企业性质标签和状态标签 MUST 带可读文字。操作图标 MUST 使用线条风格的内联矢量图标，不得继续使用彩色 emoji。可交互元素 MUST 有可见的悬停、按下和焦点状态；正文与背景的对比度 MUST 达到 4.5:1，标签文字也必须满足可读性。

#### Scenario: 状态可读

- **WHEN** 用户查看状态列
- **THEN** 每个状态显示对应颜色的圆点和状态文字，色觉障碍用户仍能通过文字识别状态

#### Scenario: 企业性质标签可读

- **WHEN** 用户查看企业性质标签
- **THEN** 标签包含「央企」「国企」「私企」或「其他」文字，而不只是色块

#### Scenario: 图标一致

- **WHEN** 用户查看搜索、查看详情、删除和设置入口
- **THEN** 图标为同一线宽和颜色的矢量图标，不出现 emoji 的平台差异

#### Scenario: 键盘焦点可见

- **WHEN** 用户用 Tab 键移动到按钮、输入框或列设置控件
- **THEN** 当前焦点有清晰的描边或高亮，不与悬停态混淆

### Requirement: 响应式布局

在窄视口下，进度页顶栏、筛选栏和摘要行 MUST 自动换行或收起，不得出现横向页面溢出；状态筛选 SHOULD 支持横向滚动。宽视口下展开的数据概览 MUST 使用多列布局，表格 MUST 保持至少一个可用滚动区域。侧栏和全屏模式切换后，布局 MUST 不丢失当前筛选、列配置和概览展开状态。

#### Scenario: 窄侧栏布局

- **WHEN** 投递进度页在 400 CSS 像素宽下显示
- **THEN** 顶栏操作换行或收起，筛选和摘要不横向溢出，表格仍可滚动查看

#### Scenario: 宽屏概览

- **WHEN** 投递进度页在 1440 CSS 像素以上宽度展开数据概览
- **THEN** 统计卡片和图表使用多列布局，表格仍保留可用的垂直空间

#### Scenario: 模式切换保状态

- **WHEN** 用户在侧栏设置筛选和企业性质筛选后切到全屏
- **THEN** 筛选条件、列配置和概览展开状态保持一致
