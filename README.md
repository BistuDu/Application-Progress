# JD 投递追踪 · 面试准备助手

一个在当前浏览器使用的 Chrome／Edge 扩展，把 **岗位投递、项目问答、八股题库和每日复习** 放在一起。

在招聘页框选 JD，交给你配置的模型提取信息，核对后保存投递记录；准备面试时，整理项目追问与通用技术问答，再用每日回想、自评和间隔复习持续巩固。

[安装使用](#一三步上手) · [投递进度](#四投递进度表) · [面试知识库](#五面试知识库) · [数据与隐私](#七数据与隐私) · [开发验证](#十开发与自检)

| 功能 | 使用方式 |
| --- | --- |
| JD 识别与投递管理 | 框选／整屏截图 → 模型识别 → 人工核对 → 跟踪状态、日期、下一步和统计 |
| 独立项目库 | 保存项目概况、个人职责及面试追问；借鉴八股题库生成回答草稿，确认后采用 |
| 八股文题库 | 手动添加、截图提取或导入 Markdown／PDF／DOCX；分类、标签、全文搜索和重复核对 |
| 每日复习打卡 | 默认每天 10 题，薄弱题优先；回想 → 揭晓 → 自评，自动记录进度、连续天数与月历 |

## 一、三步上手

1. **加载扩展**：克隆本仓库，或下载并解压[扩展包](dist/job-tracker-extension-1.0.0.zip)。打开 `chrome://extensions`（Edge 使用 `edge://extensions`），开启开发者模式，点击「加载已解压的扩展程序」，选择含 `manifest.json` 的目录。最低 Chrome 版本为 116。
2. **选择开始方式**：只整理问答时，直接从扩展弹窗进入「面试知识库」；需要截图识别时，先在设置页配置模型接口并测试连接。
3. **记录或复习**：在招聘页按 `Alt+Shift+J` 框选 JD，等待识别后核对保存；或在知识库手工添加问答，到八股题库的「每日复习」开始学习。

加载的目录需要保留在原位置。ZIP 必须先解压，不能直接当作扩展安装。

更新后，在扩展管理页点击「重新加载」，再刷新已打开的网页和知识库页面。浏览器若要求重新确认网站权限，按提示授权。数据在当前浏览器保存，更新前可先导出备份。

## 二、模型接口配置

只有截图识别、文档中的模型提取和 AI 回答需要配置接口：

| 设置项 | 填写内容 |
| --- | --- |
| 接口地址 | 服务商提供的 OpenAI 兼容接口地址 |
| API Key | 你自己的接口密钥 |
| 模型名 | 服务商实际提供、且有权使用的模型标识；截图任务需要支持图片输入 |

当前源码预填 `https://api.deepseek.com` 和 `deepseek-flash`，它们是可修改的默认设置。请以自己的服务商配置及设置页「测试连接」结果为准；预填值不保证接口、权限或视觉能力可用。识别速度与质量取决于模型、网络和图片内容。

安装后会自动打开设置页，也可从扩展弹窗右上角 ⚙ 进入。API Key 保存在本机 `chrome.storage.local`，模型请求使用你配置的接口，不会通过本项目的服务器中转。

## 三、怎么用

### 网页灵动岛

- 普通 HTTP／HTTPS 顶层网页默认显示，初始在右上角；浏览器内置页、扩展页和 Chrome 应用商店不显示，iframe 内不重复显示。
- 收起为 **56×36** 单图标磨砂胶囊；点击展开约 **212×44** 横条，只有 **框选 JD / 框选题目 / 投递进度 / 面试知识库** 四个图标和末尾「更多」。名称在悬停／键盘聚焦时显示，点击外部收起；磨砂、菜单与任务状态跟随系统浅深色，采用24px模糊、78%表面浓度及280ms形变。支持系统减弱动态效果，滤镜不可用时回退为同色实底。
- 拖动图标可自由移动，松手后保存；所有网站共用一个归一化位置。小窗口临时限制边界，恢复窗口时回到记忆位置，不自动吸边。
- 点击横条「更多 → 在此网站关闭」或扩展弹窗里的「在此网站关闭」，按 hostname 保存开关：HTTP／HTTPS、端口和路径共用，子域名独立。其他同站标签立即同步，刷新和重启后保留。
- Enter／Space 激活入口，Tab 切换；「更多」支持方向键，Escape 先关闭菜单并返回更多，再收起横条并返回图标。隐藏后可用扩展弹窗重新开启，也可到设置页「网页胶囊」恢复已关闭的网站；横条「更多」与扩展弹窗的「重置位置」只恢复右上角，不清空网站开关。弹窗分别提示页面不支持、网站偏好关闭和网站权限不足。
- 所有截图入口共用截图前隐藏与绘制确认，胶囊、菜单、提示和阴影都不会进入识别图片。切换标签、窗口或导航时停止本次截图并提示重试。
- 框选和完整核对界面运行时胶囊避让；识别时显示真实耗时和取消，不显示虚假百分比。同页只处理一个任务，其他网页保持空闲。关闭网站胶囊后仍能从原入口截图，原中心状态界面接管取消。
- 「已识别，待核对」表示候选结果；只有用户保存成功才显示「已保存」。取消会同时中止页面任务和后台请求；迟到结果不会再打开核对页或自动保存。

**网站权限**：正式 manifest 使用必需的 `<all_urls>`，让胶囊能自动接入普通网页，也让网页按钮在未先点击扩展工具栏时主动截图。升级时浏览器可能要求重新确认网站权限。胶囊空闲只读取自己的位置、网站开关和当前 hostname，不读取正文、不截图、不调用模型；模型调用与密钥仍留在后台。

### 两种识别方式

| 操作 | 说明 |
| --- | --- |
| 点扩展图标 → **框选识别 JD** | 拖拽圈出 JD 区域，精确、识别质量最好，也最省 token |
| `Alt+Shift+J` | 同「框选识别」，不用开弹窗 |
| Alt+Shift+K（或弹窗 → **整屏识别 JD**） | 直接截当前整屏送识别，一步到位 |
| 右键网页 → **记录这个岗位** | 同上两种模式，在右键菜单里选 |
| 弹窗 → **框选识别题目**（或右键 → **提取八股文题目**） | 圈选网页上的题目区域，识别后到知识库页面核对，**不生成岗位记录** |

两种方式都只截**当前可见屏幕**，所以 JD 太长时先滚动到关键区域再圈选。

### 识别流程

圈选 → 页面显示「正在识别」→ 模型返回后打开审阅面板 → 核对／修改字段 → 保存。

审阅面板里可以直接改公司、岗位、地点、薪资、类型、学历、截止时间、投递方式、**状态**、投递日期、下一步、技能关键词、JD 正文、任职要求、备注。识别结果有偏差就在这一步改掉，不用去别的地方编辑。识别过程中可以随时「取消识别」。

### 重复提醒

如果同一个公司+岗位已经记录过，面板顶部会提示已有记录，可以选择「仍然保存为新记录」或直接打开进度表查看。

## 四、投递进度表

点弹窗里的「打开进度表」，或按 `Alt+Shift+L`。

![详情抽屉](docs/screenshots/05-detail-drawer.jpg)

- **总览卡片**：总记录 / 本周新增 / 进行中 / 面试及以后（面试率）/ Offer（转化率）/ 拒绝结束（含待跟进数）
- **投递漏斗**：累计走到过每个阶段的岗位数 + 百分比 + 当前停留在该阶段的数量
- **近 8 周新增**、**来源分布**、**高频技能关键词**（帮你找复习重点，点关键词可直接筛选）
- **表格**：行内直接改**状态**和**投递日期**，双击行打开详情抽屉
- **详情抽屉**：原始截图、完整 JD、任职要求、状态时间线（每次改状态都会留痕）、识别用时与 token 用量
- **筛选**：全文搜索（含 JD 内容）、状态多选、来源、时间范围、只看有下一步的
- **批量**：勾选多条 → 批量改状态 / 批量删除
- **手动添加**：没截图也能补一条记录
- **导出**：CSV（Excel 直接打开不乱码）/ Markdown / JSON 完整备份（含截图）/ 复制 Markdown 到剪贴板

导出的 Markdown 是「公司 | 岗位 | 状态 | 投递时间 | 记录时间 | 地点 | 薪资 | 下一步 | 备注」表格 + 状态变化明细 + 岗位详情，可以直接粘进笔记或表格工具。

### 状态词表

默认 7 个状态：

`已投递` · `测评中` · `一面` · `二面` · `三面` · `HR面` · `Offer`

在设置页可以按 `名称|颜色` 的格式自由增删改。

## 五、面试知识库

入口：弹窗里的「面试知识库 →」、进度表右上角「面试知识库」、右键菜单「打开面试知识库」。页面分两个分区：**项目库**（左侧项目列表，右侧项目概况与该项目问答）和**八股文题库**（左侧分类，中间搜索/标签/题目列表，右侧题目详情）。

### 手工维护

- **项目**：填名称、简介、个人职责即可创建，**不需要关联任何岗位投递记录**；同一个项目可以用于多家公司的面试。删除项目时会先告诉你将同时删除多少道问答。
- **题目**：题目不能为空，**答案可以留空**，过后在题库里补。每题只保存**一份当前答案**，修改后旧答案不会以任何形式留存副本。
- **阅读与新增**：项目库与八股题库右下角固定“＋新建问答”，长内容滚动到底仍可使用；项目需先选定。题目使用更大字号与强调色，答案默认折叠，点击题目或键盘展开，支持当前筛选范围全部展开／折叠。搜索仍包含折叠答案全文。编辑或核对时隐藏固定入口，防止遮挡。
- **题目排序**：拖动项目问答卡片或八股题目列表左侧的六点手柄调整先后顺序，也可聚焦手柄后按 ↑／↓ 移动。刷新与 JSON 备份恢复后保留顺序；筛选时按拖到的目标题定位，其他题目的相对次序保留。项目题只能在同一项目内排序，编辑期间暂停排序；不会改变答案内容、更新时间或已生成的复习计划。
- **八股文组织**：单层自定义分类（一题一个分类）+ 多个标签；未指定分类的题进「未分类」。搜索同时匹配题目、答案正文与标签，可以和数据里的词、代码块里的技术词一起搜；分类与标签可组合筛选。
- **来源**：每道题（和每个项目）都能看到来源，也能手动补充或修改；页码不确定时留空，不猜测。

### Markdown 编辑器与快捷键

编辑框默认铺满可用区域，最小高度 300px，窄窗口为 260px，可继续向下拉高。点击「宽屏编辑」展开，Esc 返回；项目题、八股题、新增／导入核对与 AI 草稿使用相同编辑器。

选中文字后可使用格式工具栏或以下快捷键。Mac 的 `Mod` 为 `⌘`，Windows／Linux 为 `Ctrl`；Mac 的 `Alt` 对应 `Option / ⌥`。

| 操作 | 快捷键 |
| --- | --- |
| 加粗／斜体 | `Mod+B` ／ `Mod+I` |
| 插入链接／行内代码 | `Mod+K` ／ `Mod+E` |
| 插入代码块 | `Mod+Shift+K` |
| 有序／无序列表 | `Mod+Shift+7` ／ `Mod+Shift+8` |
| 一级／二级／三级标题 | `Mod+Alt+1` ／ `2` ／ `3` |
| 蓝色／红色／绿色加粗 | `Mod+Alt+4` ／ `5` ／ `6` |
| 编辑／预览切换 | `Mod+Shift+P` |
| 调用当前保存按钮 | `Mod+S`，继续执行原有核对和校验 |
| 缩进／反缩进 | `Tab` ／ `Shift+Tab`；Esc 后再按 Tab 可离开文本框 |

- 同色加粗再次使用可取消，换色会替换旧标记；撤销／重做沿用系统快捷键。编辑器内可展开「快捷键说明」。
- 格式操作只替换选区附近的必要文本，保留选区、编辑区和外层滚动位置，避免长源码加粗时闪动或向上跳转。
- 中文引号紧贴正文也能加粗，例如 `以**“HEAD 提交 → 当前磁盘内容”**为比较范围`；转义星号与代码中的星号仍保留字面含义。
- 原文按 Markdown 保存，预览支持标题、列表、引用、表格和代码围栏，并经过安全清洗。彩色加粗以带固定 class 的 `<strong>` 保存，插件阅读、预览和复习页均显示颜色；在外部 Markdown 阅读器中仍保留加粗，颜色取决于其样式。

### 录入方式

| 方式 | 入口 | 说明 |
| --- | --- | --- |
| 手工新增 | 「＋ 新增问答」/「＋ 新建项目」 | 最快，答案可以留空 |
| 网页框选 | 弹窗「框选识别题目」或右键菜单 | 圈选网页上的题目区域，一张图里的多道题会拆成多条候选 |
| 上传图片 / 粘贴图片 | 工具栏「图片录入」/ 在页面上直接 `⌘V`（`Ctrl+V`） | 已有截图不用重新截 |
| Markdown 文件 | 工具栏「文件导入」 | **本地分题，不需要 API Key**；本应用导出的题库 Markdown 可以原样再导入 |
| PDF | 工具栏「文件导入」 | 文字页本地提取；没有文字的扫描页用图像识别；能确定的页码会记录 |
| DOCX | 工具栏「文件导入」 | 标题/列表/表格转成受控 Markdown 后再分题；旧版 `.doc` 会提示先另存为 DOCX／PDF |
| 简历 → 项目 | 项目库「上传简历提取」 | 只提取项目名称、简介与个人职责，**不会自动生成面试问答，也不会保存未勾选的项目** |

### 核对与重复题

所有识别结果（图片、文件、网页框选）都先进入**核对面板**，不会直接写进正式库：

- 可以改题目与答案边界、补充来源、删除候选、逐条决定是否保存；**取消核对不会改动正式库**。
- 与已有题目**完全相同**时，会让你选择「保留已有答案 / 采用这条答案 / 把两份答案都放进编辑框人工整理」，**不会自动覆盖**；只是**说法接近**的题标记为「可能重复」，由你判断是否同题。
- 同一批导入里的重复题同样逐条处理；**还有没处理的重复题时不允许保存**，避免悄悄建出两条一样的题。
- 项目问答只在同一个项目内比对重复，和八股文题库互不影响。

### AI 参考与回答草稿

项目问答上有「AI 参考生成」按钮：

1. 按项目简介、个人职责和当前题目自动检索八股文题库，列出候选并显示**匹配依据**（命中的技术词）。
2. 你可以取消任意候选、展开查看答案，也可以搜索整个题库手动添加——**生成请求只会包含你最终勾选的参考题**。
3. 生成前会明确区分「参考资料是通用知识」与「项目资料是你的真实经历」；项目里没有的指标与贡献会写成「待补充：…」占位，参考题里的示例数据不会被当成你的项目事实。
4. 草稿与已有答案并列显示，**只有点「保存采用」才会更新答案**；取消或生成失败都不改动原来的答案。
5. 保存后会记录本次用到的参考题（标题 + 使用时间）。参考题后来被修改或删除，**已有答案保持原样**，只在参考信息里标出「已修改」或「来源不可用」。
6. 生成可以随时取消；如果生成期间题目或答案被改过，会拒绝直接覆盖，要求重新核对。

### 每日八股复习与打卡

八股文题库内点击「每日复习」。默认每天 10 题，可设置 1–100 题、分类和多个标签（同时匹配）。当天首次开始后固定题目与目标，设置修改次日生效。只有非空答案的八股题参与，题量不足按实际数量，不重复凑数；项目题不参与。

先看题目，默想或填写可选临时回答，再揭晓已有 Markdown 答案，最后自评「记住了／还需复习」。**临时回答仅存在当前页面内存，离题／刷新即清空，不写入存储、备份或模型请求**。保存自评成功才进入下一题，失败可重试。

- 选题按到期薄弱题、其他到期题优先，不足时随机补充；随机补充也可能提前抽到未到期题。
- 首次记住后安排 1 天，连续记住依次为 3、7、14、30 天，之后维持 30 天；「需复习」重置并安排次日。
- 今日进度自动保存，关闭／重开继续，已揭晓未自评的题重新隐藏答案。日期按设备本地日历；跨天留存未完成记录并重新安排，不补签。时区变化后按新的当地日期读取计划。
- 全部有效题均自评后自动打卡，「需复习」也算完成学习；空计划不打卡。可查看连续天数、切换月份及点击日期查看每题自评。今天尚未打卡时，连续天数显示截至昨天的连续记录。
- 未评分题删除或答案清空后会从有效目标排除并提示；题答在另一页更新后需重新揭晓。历史保留当时题目标题和自评，已删除题标为不可用，不存历史答案副本。

### 备份、恢复与导出

- **JSON 完整备份**：包含两个库、分类、标签、来源、AI 参考关系，以及学习设置、间隔、每日计划与历史，带格式标识与版本号（当前 v2）；**不含 API Key、原始文档、原始截图或临时草稿**。
- **版本兼容**：新版可读旧 v1 库和备份；v1 备份不含学习记录，恢复预览会提示清空当前学习记录。v2 备份不能导入旧版扩展；如需回滚，应使用升级前的 v1 备份，升级后的学习记录无法带回旧版。恢复会替换两库及全部学习记录，Markdown 仍只包含知识正文。
- **恢复**：先完整解析并校验版本、必要字段、项目归属与分类引用，展示「当前数量 → 备份数量」的替换范围，确认后一次性替换知识库。版本不支持、内容非法、取消或写入失败都不会改变当前知识库；面板里可以先下载一份当前备份再恢复。
- **Markdown 导出**：项目库按项目、题库按分类导出，保留题目/答案的标题列表与代码围栏，并带上标签、来源和项目答案的 AI 参考题；导出的题库 Markdown 可以重新导入并在核对面板里恢复标签与分类。答案中的任意层级标题、Q／A 示例和代码空行不会被拆成新题，空项目和空库也不会产生假题目。内嵌的导出标记用于界定答案，若手动编辑导出文件使边界失配，导入会明确报错，请重新导出或使用普通 Markdown 题库格式整理后导入。
- 这些操作与岗位数据的 JSON／CSV／Markdown 完全独立：恢复知识库不会碰岗位记录、状态词表或模型设置。

### 本地保存与隐私边界

- 知识库只存在本机 `chrome.storage.local` 的 `knowledgeLibrary` 一个键里，按字段白名单写入。
- 识别用的**截图、上传的图片与文件字节只在处理期间存在于内存**，识别完成、取消或失败后即释放；不会写进 `chrome.storage.local`、不会进岗位记录的兜底缓存，也不会进备份。
- 模型请求只在后台 service worker 发出，知识库页面拿不到 API Key；页面与后台之间只传题目、答案、标签、来源等纯文本。
- Markdown 渲染用随扩展分发的 Marked + DOMPurify：脚本、事件属性与 `javascript:` 链接不会执行，预览也不会自动加载答案里的图片附件。所有第三方依赖都固定版本放在 `src/vendor/`，不请求任何 CDN。

### 已知限制

- **旧版 `.doc`** 需要先用 Word 另存为 `.docx` 或导出 PDF。
- 单个文件超过 **20 MiB**、PDF 超过 **50 页**时会提示拆分，不会静默截断；多页识别可以取消，失败页可以单独重试。
- 自动匹配基于关键词与分类标签，**中文同义改写**可能匹配不到，这时请用「搜索整个题库」手动添加参考题。
- 扫描件与排版复杂的 PDF，题目/答案边界可能需要在核对面板里手工调整。
- 「可能重复」只做提示，不会自动合并；同一道题的多种问法默认按不同题目保存（如需合并请用「人工整理」）。

## 六、设置项说明

- **截图最长边 / JPEG 质量**：默认 1800px / 0.9。调大更清晰但更慢更贵。
- **最多保留截图条数**：默认 300 条，超出后只删旧截图，记录本身保留。
- **保存截图**：关掉后只存文字，省空间。
- **默认状态**：新记录初始状态，默认「已投递」。
- **保存后自动关闭面板 / 自动打开进度表**。
- **识别提示词**：可以完全自定义让模型抽哪些字段（占位符 `{{pageTitle}}`、`{{pageUrl}}` 会自动作为辅助上下文）。
- **数据**：导出全部数据（JSON/CSV/Markdown）、导入 JSON 备份（按 id 覆盖、按公司+岗位去重）、清空全部记录（需输入「清空」二次确认）、查看存储占用。

## 七、数据与隐私

- 记录、截图与 API Key 持久保存在本机 `chrome.storage.local`；识别与 AI 辅助使用你自己配置的模型接口。
- JD 识别发送选中的截图；知识库识别发送选中的图片或提取的文档文字；项目回答生成发送项目资料、当前问题及你最终选定的参考问答。请求体使用 `Authorization: Bearer <你的 Key>`。
- 导出的 JSON 备份包含截图（base64），注意别误传到公开仓库；CSV/Markdown 不含截图。
- **面试知识库**保存整理后的项目、问答、分类标签、来源和学习记录；识别用图片与上传文件不会持久保存，临时回想文本不落库。知识库 JSON 备份不含 API Key、原始附件或截图。

## 八、常见问题

**提示「还没有配置 API Key」** —— 打开设置页填好 Key；安装后设置页会自动打开一次。

**测试连接报 401/403** —— Key 不对或没有该模型权限，回设置页检查；报 404 则是「接口地址」或「模型名」写错了。

**提示模型不接受图片输入** —— 当前模型不支持视觉，换一个支持 `image_url` 的模型。

**识别出来是空的** —— 模型偶发空返回时扩展会自动重试一次；两次都空说明圈选范围内可能没有文字，重新圈一次，或圈小一点、圈得更准。

**识别很慢或很贵** —— 调小设置里的「截图最长边」，或者框选时只圈 JD 正文而不是整屏。

**截图失败 / 无法截图** —— 浏览器内置页面（`chrome://`、扩展页、应用商店页）不允许截图，换普通网页；本地文件页面（`file://`）需要在 `chrome://extensions` 里为本扩展开启「允许访问文件网址」。

**整页长截图支持吗** —— 不支持，扩展只截当前可见区域，用「整屏 + 框选」组合覆盖；JD 太长就分两次记。

## 十、开发与自检

```bash
# 岗位离线检查
JDT_API_KEY='' node scripts/selftest.mjs

# 可选：核心逻辑自检与真实接口调用
node scripts/selftest.mjs --from-zcode        # 从 ~/.zcode/v2/config.json 找 deepseek-flash 的 key
JDT_API_KEY=sk-xxx node scripts/selftest.mjs  # 或直接给 key
node scripts/selftest.mjs --image ./shot.jpg  # 换自己的截图

# 真实浏览器端到端测试（隔离 profile，不会碰你正在用的浏览器）
node scripts/e2e-cdp.mjs --from-zcode

# 岗位浏览器回归（本地 mock，无真实 Key）
node scripts/e2e-cdp.mjs --mock

# 网页胶囊：离线 + 正式 manifest 的隔离浏览器验收
node scripts/island-selftest.mjs
node scripts/island-e2e.mjs

# 知识库离线自检：不需要 Key、不联网、不开浏览器
node scripts/knowledge-selftest.mjs

# 知识库完整界面回归：无 Key，模型相关分支明确跳过
JDT_API_KEY='' node scripts/knowledge-e2e.mjs

# 问答阅读、排序、编辑器与每日复习定向回归
JDT_API_KEY='' node scripts/knowledge-e2e.mjs --review-only

# 可选：知识库界面 + 真实模型
node scripts/knowledge-e2e.mjs --from-zcode
```

`selftest.mjs` 覆盖 URL 归一化、JSON 抽取容错、字段别名映射、空返回重试、落库、状态时间线、统计漏斗、CSV/Markdown/JSON 导出、导入去重，并用真实接口跑一张样例图。

`e2e-cdp.mjs` 会启动一个安装了本扩展的 Chromium，走完「截图 → 框选 → 识别 → 改状态 → 保存 → 看板统计 → 抽屉 → 搜索 → 设置页 → 连通性测试 → popup」全流程，并把各界面截图写到 `tmp/e2e/`。

`knowledge-selftest.mjs` 用 `chrome.storage` 替身和打桩的 `fetch` 覆盖：知识库容器的字段白名单与关系校验、CRUD 与级联、**串行写入与 revision 冲突**、候选规范化与重复题决策、参考题检索、JSON 备份/恢复（含未知版本、非法归属、写入失败与取消）、Markdown 导出往返，以及模型任务的错误归一化、空返回重试、超时与取消、乱序返回与「只发送选定参考」。

`knowledge-e2e.mjs` 在真实浏览器里验证：页面与本地依赖加载、Markdown 预览的 XSS 清洗、手工问答与分类标签搜索、跨页面编辑冲突、Markdown／PDF／DOCX 导入、图片上传与粘贴、网页框选交接、AI 草稿与参考来源追踪、备份恢复与 Markdown 导出，并审计 `chrome.storage` 确认知识库里没有图片、文件字节或 API Key；产物写到 `tmp/e2e-knowledge/`。

> 自动化脚本会寻找本机可用的 Chromium／Chrome for Testing（包含 Playwright 缓存），也可用 `JDT_CHROME` 指定浏览器路径。测试安装方式与手动「加载已解压的扩展程序」分开。
> 浏览器测试使用临时扩展副本与隔离 profile，保留正式 manifest，不补测试权限。胶囊与岗位 mock 用例只连接本地可控模型，无真实 Key；真实模型测试仍须显式提供配置。
